# KMP migrace — fáze 7–9: stringy, ViewModely, úklid

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Přesunout 423 string resources do Compose Resources a 12 ze 13 ViewModelů do `commonMain`, čímž se migrace uzavře — v `:app` zůstane jen Compose UI, navigace a platformní adaptéry.

**Architecture:** Stringy jdou první, protože na nich závisí `FoodAllergenHelper` (`displayRes: Int`) i dva ViewModely (`@StringRes`). Migrace stringů se nejdřív ověří na jednom jediném řetězci — teprve když prokazatelně funguje včetně přepínání jazyka, přesune se zbylých 422. ViewModely následují.

**Tech Stack:** Compose Multiplatform Resources, androidx.lifecycle ViewModel (KMP), Koin 4.x

**Spec:** `docs/superpowers/specs/2026-09-01-kmp-migration-design.md`

**Předchozí plány:** `2026-09-01-kmp-faze-0-2.md` a `2026-09-01-kmp-faze-3-6.md` — oba musí být dokončené. Tento plán předpokládá, že `commonMain` obsahuje celou doménovou a datovou vrstvu a neobsahuje žádný android import.

## Global Constraints

- Kotlin 100 %, žádný Java kód
- Závislosti vždy přes version catalog `gradle/libs.versions.toml`
- Veškerý text UI v češtině; `values-cs/` jsou primární, `values/` je anglický fallback
- Ikony v UI vždy jako samostatné `Icon()` composable — **nikdy emoji ani Unicode znak vložený do string resource**
- Po každém tasku musí platit: `./gradlew :shared:compileKotlinIosArm64` je zelené
- **Tento plán nesmí změnit žádné chování aplikace ani jediný zobrazený text.**

## Největší riziko tohoto plánu

Aplikace přepíná jazyk přes `AppLocaleHelper`, který na API 33+ používá `LocaleManager.applicationLocales` a níž `createConfigurationContext` v `MainActivity.attachBaseContext()`. Obojí ovlivňuje **Android resource systém**.

Compose Resources si ale locale řeší samo. Není předem jisté, že per-app language nastavené přes `LocaleManager` se v Compose Resources projeví — zvlášť na API < 33, kde se spoléhá na obalený `Context`.

**Proto Task 1 končí důkazem na jednom stringu.** Pokud přepínání jazyka nefunguje, plán se zastaví a použije se fallback ze specu (riziko č. 5): stringy zůstanou v `res/`, ViewModely místo `@StringRes Int` vrátí sealed třídy a `:app` je přeloží. Fáze 7 se tím vypustí a fáze 8 se udělá jinak.

## Známé zděděné chyby — neopraveny záměrně

Migrace zachovala chování beze změny. Tyto věci jsou rozbité už před ní:

1. **Ošetření HTTP 503 je mrtvý kód.** `FoodRepositoryImpl.searchFoodByName()` chytá
   `Exception` a vrací `emptyList()`, takže výjimka nikdy nedoteče do `FoodLogViewModel`,
   kde se testuje status 503. `isServiceUnavailable` se nikdy nenastaví.
2. **8 z 13 ViewModelů volá DAO přímo**, mimo repository pattern.
3. **Food sub-flow nesdílí instanci `FoodLogViewModel`** — každá obrazovka má vlastní,
   stav se předává nav argumenty. CLAUDE.md tvrdil opak.
